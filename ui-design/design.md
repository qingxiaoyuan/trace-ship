# TraceShip 软件版本发布管理与提交规范审查系统 — 界面设计说明书

## 1. 文档概述

### 1.1 编写目的

本文档为 **TraceShip 软件版本发布管理与提交规范审查系统**（以下简称“本系统”）的前端界面设计说明书，用于指导前端开发人员依据设计稿完成页面实现，确保企业蓝风格、左右导航布局、各功能模块视觉与交互一致性。

### 1.2 适用范围

本说明书适用于本系统所有前端页面，涵盖登录、工作台、项目管理、仓库管理、凭证管理、提交规范审查、Tag 生成与发布、Jenkins 构建、工作流审批、发布看板、系统管理等模块。

### 1.3 参考文档

- `trace-ship-ui.html` — 企业蓝 · 左右布局高保真原型
- `feat.md` — 系统需求文档

## 2. 设计目标与原则

### 2.1 设计目标

- **专业性**：面向软件发布与研发管理，界面风格沉稳、信息层级清晰。
- **高效性**：核心数据与待办事项一目了然，高频操作一键触达。
- **可追溯性**：发布、审批、构建、提交审查全流程留痕，便于审计。
- **协作性**：项目、成员、凭证、工作流配置统一入口，支持团队协同。

### 2.2 设计原则

| 原则       | 说明                                   |
| ---------- | -------------------------------------- |
| 清晰分层   | 信息按重要性分层展示，避免视觉拥挤     |
| 状态可视化 | 通过颜色标签、图标、进度条直观呈现状态 |
| 操作前置   | 高频操作（新建发布、审批）置于显眼位置 |
| 一致性     | 同类组件保持一致的视觉与交互表现       |
| 容错性     | 关键操作（删除、清空）需二次确认       |

## 4. 全局布局设计

### 4.1 登录页

**布局描述：**

- 全屏浅蓝紫渐变背景：`linear-gradient(135deg, #F0F9FF 0%, #EFF6FF 50%, #F5F3FF 100%)`。
- 页面中央为登录卡片，最大宽度 `max-w-md`（448px），圆角 `rounded-2xl`（16px）。
- 卡片使用毛玻璃效果：`background: rgba(255,255,255,0.95)`、`backdrop-filter: blur(10px)`，白色半透明边框。

**卡片内容：**

- **品牌区**：上方居中展示 Logo（44×44px 蓝紫渐变方块，内含闪电图标）、系统名称 `TraceShip`、副标题“软件版本发布管理与提交规范审查系统”、版本徽章 `v2.4.0`（左侧带蓝色圆点）。
- **登录方式切换**：顶部两个 Tab —— “域账号登录”（默认选中，蓝色下划线）、“本地账号”。
- **表单字段**：
  - 用户名输入框（默认值 `zhangsan`，占位提示“请输入域账号/用户名”）。
  - 密码输入框（默认值隐藏显示为圆点，占位提示“请输入密码”）。
  - “记住我”复选框 + “忘记密码？”链接。
- **登录按钮**：通栏主按钮，文字“登 录”。
- **底部提示**：首次登录将自动同步 LDAP 用户信息。

**侧边导航栏（宽度：240px）**

## 5. 页面详细设计

### 5.1 工作台（仪表盘）

**页面定位**：系统首页，展示发布核心指标与待办。

**布局结构**：

```
┌────────────────────────────────────────────────────────────────┐
│  面包屑：工作台 / 仪表盘                                         │
├────────────────────────────────────────────────────────────────┤
│  [近7天发布数] [待审批数] [构建成功/失败] [Commit合规率]         │
├──────────────────────────────┬─────────────────────────────────┤
│                              │                                 │
│      最近发布表格             │     我的待办                     │
│      （占左侧 2/3）           │     （占右侧 1/3）               │
│                              │                                 │
│                              │     非法提交预警卡片              │
│                              │                                 │
└──────────────────────────────┴─────────────────────────────────┘
```

**统计概览卡片（4 列等分）**：

| 指标          | 数值   | 辅助信息                     | 图标背景色 |
| ------------- | ------ | ---------------------------- | ---------- |
| 近 7 天发布数 | 12     | 绿色标签 `+20%` + “较上周”   | 蓝色渐变   |
| 待审批数      | 3      | “2 个待审批 · 1 个即将超时”  | 琥珀色渐变 |
| 构建成功/失败 | 10 / 2 | 红色标签 `2 失败` + “需关注” | 红色渐变   |
| Commit 合规率 | 92.5%  | 蓝色进度条（宽 92.5%）       | 靛蓝色渐变 |

- 每张卡片：白色圆角卡片、内边距 20px、标题 14px `#64748B`、数值 30px 加粗 `#0F172A`、44×44px 图标容器（渐变背景）。

**最近发布表格**：

- 卡片标题区：左侧“最近发布”+ “最近 10 条发布记录”，右侧“查看全部”次按钮。
- 表格列：版本号 | 项目 | 类型 | 状态 | 时间。
- 示例数据：
  - `v2.4.1` / 核心交易平台 / 正式（蓝标签）/ 已发布（绿标签）/ 2026-06-15
  - `v2.4.1-test.3` / 核心交易平台 / 测试（琥珀标签）/ 构建中（琥珀标签）/ 2026-06-14
  - `v2.3.9` / 数据中台 / 正式 / 已发布 / 2026-06-10

**我的待办**：

- 列表项为浅灰背景圆角卡片，左侧带 36×36px 图标（蓝色/琥珀），标题加粗，副标题为申请人与时间，右侧“去审批”蓝色文字按钮。
- 示例：审批发布 `v2.5.0`（李四 · 10 分钟前）、审批发布 `v2.4.2-test.1`（王五 · 1 小时前）。

**非法提交预警卡片**：

- 左侧 56×56px 琥珀色图标，中间大号数字 `7` + “待处理的不合规 commit”，右侧“查看”次按钮。
- **卡片不使用左侧彩色边条，仅通过图标与背景色表达预警含义。**

### 5.2.3 项目新增/编辑弹窗

**弹窗目标**：用于创建新项目或编辑项目基本信息。

**弹窗规格**：

- 标题：新增项目 / 编辑项目。
- 宽度：最大 560px，与系统其他弹窗保持一致。
- 底部操作：取消（次按钮）、保存（主按钮），右对齐。

**表单字段**：

| 字段 | 组件 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| 项目编码 | 输入框 | 是 | 唯一编码，创建后不可修改；建议大写英文 + 连字符，如 `CORE-TRADE` |
| 项目名称 | 输入框 | 是 | 项目中文/英文显示名称 |
| 项目负责人 | 下拉选择 | 是 | 从系统用户中选择，负责项目日常管理与审批 |
| 描述 | 多行文本域 | 否 | 项目范围、业务说明等补充信息 |
| 状态 | 单选 | 是 | 启用（默认）/ 停用 |

**交互说明**：

- 点击“保存”时前端校验必填项，校验通过后关闭弹窗并提示保存成功（演示阶段使用 alert）。
- 点击遮罩、关闭按钮或“取消”关闭弹窗，不保存数据。

### 5.3.1 连通性测试

- 点击操作列「测试」按钮后，按钮文字变为「测试中…」并进入禁用态，模拟后端请求约 1.2 秒。
- 测试完成后恢复按钮原状，并根据结果弹出提示：
  - 成功：绿色提示「仓库 {名称} 连通性测试：连接成功」。
  - 失败：红色提示「仓库 {名称} 连通性测试失败：凭证失效或地址不可达」。
- 示例数据中 `core-trade-backend`、`core-trade-frontend` 测试成功，`trade-configs` 测试失败，与其「异常」健康状态保持一致。

- 标签颜色：发布（蓝）、审批（绿）、修改（琥珀）、删除（红）、新增（蓝）。
- 结果标签：成功（绿）、失败（红）。

## 7. 交互设计

### 7.1 通用交互

**页面切换**：

- 点击侧边导航切换页面，当前项高亮，主内容区淡入（200ms ease-out）。
- Header 面包屑同步更新。

**Tab 切换**：

- 横向 Tab 点击后底部下划线与文字颜色变化；对应内容区淡入显示。
- 适用于项目详情、工作流审批、系统配置等场景。

**表格交互**：

- 表头固定样式，数据行悬停背景变化。
- 操作列文字按钮悬停变为主色深色。

**表单交互**：

- 输入框聚焦外发光；下拉框点击展开面板。
- 必填项标签左侧带红色星号。

### 7.2 登录交互

- 点击“域账号登录 / 本地账号”切换 Tab，选中项文字加粗、主色下划线。
- 点击“登录”后进入主界面，登录页隐藏。

### 7.3 Tag 生成向导交互

- 步骤切换时：顶部圆形节点状态变化（待处理 / 当前 / 已完成），连线高亮。
- 每步底部固定“上一步”与“下一步/提交审批”按钮。
- 第二步支持 commit 复选、全选、合并、排除；右侧统计与 AI 风险提示同步更新。
- 第三步支持保存草稿、导出 Word/PDF、提交审批。

### 7.4 工作流设计器交互

- 切换至“流程定义”Tab 后初始化 LogicFlow 画布。
- 左侧节点工具箱支持拖拽节点到画布。
- 顶部“重置”清空画布，“保存流程”获取图数据并提示保存成功。
- 画布支持缩放、平移、节点拖拽、连线。

### 7.5 弹窗与抽屉交互

- 点击“编辑凭证”打开 Modal，点击遮罩或关闭按钮关闭。
- 点击“编辑权限”打开右侧抽屉，点击遮罩或关闭按钮关闭。
- 打开/关闭均带有 200-300ms 过渡动画。

### 7.6 通知与状态反馈

- Header 通知铃铛带未读红点，有新待办或告警时数字/颜色变化。
- 构建中状态使用琥珀色脉冲动画（`animate-pulse-soft`，2s 循环）。
- 操作成功/失败可通过顶部 Toast 提示（示例中未完整展示，建议采用本系统统一 Toast）。

### 8.1 分辨率适配

| 分辨率      | 适配策略                                          |
| ----------- | ------------------------------------------------- |
| ≥1920px     | 标准布局，侧边栏展开，多列卡片并排                |

| <1280px     | 最小支持宽度，表格横向滚动，弹窗/抽屉全屏或自适应 |

### 8.2 布局行为

- 统计卡片在大屏下 4 列，中屏 2 列，小屏 1 列。
- 工作台左右布局在小于 `lg` 断点时堆叠为单列。
- 工作流设计器在小屏下工具箱与画布垂直堆叠。

### 8.3 表格适配

- 列数过多时启用横向滚动，关键列（如名称、状态、操作）固定左侧。
- 小屏幕下非关键列隐藏或折叠到展开行中。

## 9. 动画与过渡

### 9.1 页面与面板切换

- 页面/面板淡入：`fadeIn 0.25s ease-out`，从 `opacity:0, translateY(4px)` 到正常。
- Tab 内容区同样使用该动画。

### 9.2 悬停与状态过渡

- 导航项、按钮、卡片悬停：200ms ease 过渡。
- 表格行背景色变化：150ms ease。
- 主按钮悬停时上移 1px 并增强阴影。

### 9.3 步骤与进度

- 步骤圆形节点与连线：300ms ease 过渡颜色与阴影。
- 进度条宽度变化建议 500ms ease-out。

### 9.4 加载与脉冲

- 构建中脉冲圆点：`pulse-soft 2s cubic-bezier(0.4,0,0.6,1) infinite`。
- 数据加载建议使用卡片/表格内局部骨架屏或旋转 Loading。
