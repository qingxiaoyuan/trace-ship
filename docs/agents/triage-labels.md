# Matt 标签映射

GitHub 使用中文标签；Matt 技能中的英文名称为角色标识，调用工具时必须转换成下表中的中文名称。

| Matt 角色 | GitHub 标签 | 含义 |
| --- | --- | --- |
| bug | 缺陷 | 已有行为出现错误 |
| enhancement | 功能改进 | 新功能或既有能力改进 |
| needs-triage | 待评估 | 需要核实问题、实现现状或范围 |
| needs-info | 待补充信息 | 等待提出者补充信息或作出必要决策 |
| ready-for-agent | 可由AI开发 | 规格、验收与测试边界已明确，可交给 Agent |
| ready-for-human | 需人工开发 | 需要人工实施 |
| wontfix | 不予处理 | 明确不继续执行 |

- 纳入分流的 Issue 使用一个分类标签和一个状态标签；切换状态时移除旧状态，保留其他无关标签。
- `to-spec` 完成约定的测试边界确认后，发布的规格使用「可由AI开发」；`to-tickets` 发布用户已确认的任务时同样使用该标签，不重复分流。
- 「可由AI开发」不代表没有依赖，也不会自动启动开发。开始前读取最新正文、评论和依赖，确认前置任务已完成。
- 标签表示分流结果；负责人、关联 PR 和必要的进展评论表达实际开发进度。需要时可另用 GitHub Projects 看板，但不是 Matt 的前置要求。
- 历史归档 Issue 保持关闭，在正文说明归档原因；不强制套用活跃任务标签，不把归档关闭解释为功能完成。
- 本次现有 Issue 使用「功能改进」「待评估」「待补充信息」。其余映射在首次需要时创建对应中文标签，避免生成英文同义标签。
