# 前端可发现性优化设计

> 日期：2026-09-17
> 状态：已评审（方向确认：命令面板 + 深链回链 + 导航治理 + 工作台枢纽化，三者融合、分阶段落地）
> 范围：前端为主，二期涉及少量后端接口

## 1. 背景与痛点

用户反馈：「想用某一个功能时，找到这个功能的入口太难了」。经代码现状梳理（2026-09），痛点归为三类且同时存在：

1. **功能找不到入口**：知道有某个功能（如仓库审批流配置、打包配置、访问令牌），但不知道藏在哪个菜单、哪层 tab 里；
2. **数据找不到位置**：想找某个具体的项目/仓库/发布单/审批单，只能逐层翻列表；
3. **上下文来回跳**：在发布、仓库、打包任务之间追溯时要反复返回列表重进，链路断裂。

## 2. 现状关键事实（以代码为准）

- 顶栏搜索框是纯装饰：`frontend/src/layouts/TopHeader.tsx`（约 147-161 行）的「搜索项目、仓库、发布、提交… ⌘K」按钮无任何行为，全站无全局搜索/命令面板。
- 命名三套口径：后端菜单名（`backend/apps/account/views.py:431-462`）叫「打包任务 / 工作流审批 / 项目管理」，侧边栏 labelMap（`frontend/src/layouts/components/navMenu.ts:102-112`）叫「打包看板 / 审批中心 / 项目/产品」，路由标题（`frontend/src/router/index.tsx:83-124`）又是第三套（如 `/workflows` 标题为「工作流审批」）。
- 高频配置藏得深：仓库审批流配置在 仓库列表 → 详情 → 第 8 个 tab，且仓库详情 tab 是组件内 state，不可 URL 寻址（项目详情 tab 已可 URL 寻址，两者不一致）。
- 审批单详情无 URL：`frontend/src/pages/Workflow/index.tsx` 用页内 state 切换详情，从通知点进来只能落到列表。
- 实体间不回链：发布详情（`frontend/src/pages/Release/Detail.tsx`）中项目名、仓库名是纯文本；提交审查详情不链回仓库；打包看板任务不链回项目/仓库/发布；发布详情「打包任务」tab 只跳 `/packages` 列表而非具体任务。
- 工作台只有发布/打包视角：无项目、仓库、凭证、提交审查的入口，无「最近访问」。
- 菜单分组规则前端硬编码（`navMenu.ts` `groupRules`）：后端下发未识别 path 会被静默丢弃；`SidebarNav` 支持 badge 但无数据源；侧边栏顶部「部门/项目数」胶囊按钮无 onClick，是死 UI。
- 已有的聚合机制仅两处：打包配置收藏（`PackageGlancePanel` 常用配置区）和「新建发布」的 4 处全局入口。

## 3. 设计原则

1. 任何功能 ≤2 次操作可达（菜单一次、命令面板一步）；
2. 任何实体可被搜索或被回链直达，详情页之间形成双向链路；
3. 全站同一功能只用一个名字；
4. 消灭死 UI：没有行为的入口要么做实、要么移除；
5. 分期交付：一期纯前端快速见效，二期接后端补搜索与计数。

## 4. 方案

### 4.1 ⌘K 全局命令面板（核心）

- **唤起**：顶栏搜索框点击、快捷键 `⌘K` / `Ctrl+K`；移动端在 TabBar 左侧菜单胶囊内加入口。
- **实现**：Ant Design Modal 自绘输入框 + 结果列表；不新增 cmdk 等依赖。
- **内容三层**：
  1. **功能入口**（一期，纯前端静态注册表）：覆盖全部菜单项 + 藏在 tab 内的高频配置，如「仓库审批流配置」（跳 `/repositories/:id/audit-flow` 类深链）、「打包配置」「版本规则」「访问令牌」「LDAP 配置」等；支持中文关键词与拼音模糊匹配；
  2. **快捷操作**（一期）：新建发布、触发打包、新建凭证等，复用现有路由与弹窗；
  3. **实体搜索**（二期）：输入关键词搜项目/仓库/发布单/审批单/打包任务，防抖调用后端聚合接口 `GET /api/search/?q=`，按类型分组展示，回车直达详情。
- 注册表按权限过滤：只展示当前用户菜单可见的功能（复用 `navMenu` 的可见性判断）。

### 4.2 深链与回链补全（一期，纯前端）

- 仓库详情 tab 改为 URL 寻址：`/repositories/:id/:tab`，与项目详情对齐；旧的 `/repositories/:id` 默认重定向到首个 tab，保证外链兼容。
- 审批单详情加 URL：`/workflows/:id`；通知中的审批消息链接改为直达具体审批单。
- 回链补全清单：
  - 发布详情：项目名 → `/projects/:id`，仓库名 → `/repositories/:id`；
  - 提交审查详情 → 所属仓库；
  - 打包任务 → 关联发布 `/releases/:id`、所属仓库；
  - 发布详情「打包任务」tab → `/packages/:id`（直达任务而非看板列表）；
  - 凭证详情 → 关联仓库（已存在，保持）。
- 面包屑统一：详情页层级含实体名（如「发布看板 / V2.3.1 发布详情」），替换路由 handle.title 的泛化写法；项目/仓库详情各自手写的面包屑统一到同一组件。

### 4.3 导航与命名治理（一期 + 二期）

- **命名统一**：以后端菜单名 / 侧边栏 label / 页面标题三处一致为准，建议统一采用当前侧边栏口径（用户见得最多）：

  | 功能 | 后端菜单名 | 侧边栏 | 页面标题 | 统一为 |
  |---|---|---|---|---|
  | 打包 | 打包任务 | 打包看板 | 打包看板 | 打包看板 |
  | 审批 | 工作流审批 | 审批中心 | 工作流审批 | 审批中心 |
  | 项目 | 项目管理 | 项目/产品 | 项目/产品 | 项目/产品 |

- `groupRules` 加兜底：未识别 path 归入「其他」分组并 console 告警，不再静默丢弃。
- 侧边栏「部门/项目数」胶囊：建议移除（信息价值低），或在二期做实（点击跳 `/projects`）。
- 菜单 badge（二期）：`SidebarNav` 已有 badge 能力，接「待我审批数」挂到「审批中心」，与顶栏铃铛未读数同源。
- 「打包配置」在命令面板中直达，并在打包看板内提升可见性（默认 tab 或置顶入口）。

### 4.4 工作台枢纽化（一期，纯前端）

- 新增「最近访问」区：localStorage 记录最近访问的项目/仓库/发布/审批详情（key 如 `trace-ship.recent-visits`，上限 10 条，按时间倒序），卡片式展示。
- 新增模块快捷入口区：项目、仓库、提交审查、凭证四个入口卡片（现工作台完全没有这些模块的入口）。
- 保留现有 KPI 卡、发布流水线、打包速览、我的待办。

## 5. 分期路线

**一期（纯前端，不改后端）**

| 项 | 主要涉及文件 |
|---|---|
| ⌘K 命令面板（功能入口 + 快捷操作） | `TopHeader.tsx`、新增 `components/CommandPalette/` |
| 仓库 tab URL 化、审批单 `/workflows/:id` | `router/index.tsx`、`pages/Repository/Detail`、`pages/Workflow` |
| 实体回链与面包屑统一 | `Release/Detail`、`Commit/Detail`、`Package`、`TopHeader` |
| 命名三处统一 | `navMenu.ts`、`router/index.tsx`、后端菜单视图 |
| 菜单兜底分组、死按钮移除 | `navMenu.ts`、`Sidebar.tsx` |
| 工作台最近访问 + 快捷入口区 | `pages/Dashboard/index.tsx` |

**二期（需后端支撑）**

- 聚合搜索接口 `GET /api/search/?q=`：按权限过滤搜索项目/仓库/发布/审批/打包任务，接入命令面板；
- 「待我审批数」计数接口接入侧边栏 badge；
- 实体搜索排序优化（按最近访问/使用频率加权）。

**验收标准**

- 一期：任意菜单功能经命令面板一步直达；仓库审批流配置、打包配置可直接搜索跳转；通知可直达具体审批单；同一功能全站只有一个名字；不存在无行为的入口。
- 二期：任意实体（项目/仓库/发布单/审批单/打包任务）可通过命令面板搜索直达；「审批中心」菜单项显示待办数。

## 6. 风险与兼容

- **命名变更影响老用户习惯**：随更新日志（`/changelog`）发布说明，一次性完成切换，不做双名过渡期。
- **tab URL 化**：保留旧路径重定向，不破坏已分享链接；改造时注意 tab 内异步数据的重复加载。
- **命令面板权限**：功能索引必须按当前用户可见菜单过滤，避免「搜得到、进不去」。
- **移动端**：命令面板在 ≤768px 走全局贴底弹出（复用 `index.css` 媒体查询约定），不做自定义定位。

## 7. 不做的事（YAGNI）

- 不做菜单拖拽自定义、不做用户自定义快捷方式（收藏机制仅限打包配置，暂不推广）；
- 不做面包屑的全站重构框架，仅在详情页统一口径；
- 二期之前不做全文搜索（搜索说明、提交内容等），实体搜索只匹配名称/编号。
