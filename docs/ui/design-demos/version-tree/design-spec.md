# 产品版本二级树组件设计规格

## 设计目标

产品详情中的发布版本不再以一张没有仓库归属的扁平表展示，而是明确表达「产品包含多个软件仓库，每个软件仓库拥有自己的发布版本」这一业务关系。界面只使用现有概念：产品、软件仓库、版本、Tag、发布类型、发布人、发布时间，不引入「组件名称」「产品内名称」等额外名词。当前阶段只验证视觉和交互方向，不修改业务代码；选定方向后再沉淀为可复用前端组件，并用于产品发布版本、打包看板、打包配置等需要按仓库组织数据的场景。

## 五问设计约束

1. **叙事角色**：这是数据管理页面中的结构化浏览组件，不是营销页面。首要任务是让用户快速判断某个版本属于哪个仓库，并能在仓库之间切换或同时比较。
2. **观察距离**：用户在约一米距离使用 14～27 英寸显示器。仓库名称需在一眼范围内形成一级锚点，版本号和 Tag 使用等宽数字与较稳定的列对齐，辅助信息降低对比度。
3. **情绪基调**：冷静、专业、轻量。沿用 Trace Ship 的亮色技术后台风格，以靛蓝为主色、青色为次要强调、低饱和状态色表达正式、RC、Beta，不加入新的装饰性视觉语言。
4. **内容容量**：默认按 3～8 个仓库、每仓库 3～20 个版本设计。需要支持单仓库展开、多仓库展开、全部折叠、搜索后自动显示命中层级，以及空状态和长 Tag 的截断兜底。
5. **记忆点**：用「仓库主干—版本分支」作为唯一视觉母题。一级仓库承担分组和摘要，二级版本承担可扫描明细；连接线、缩进或左右分栏只服务于层级识别，不做额外装饰。

## 项目风格提取

设计稿沿用现有页面的 `#F6F7FB` 背景、48px 淡靛蓝网格、白色卡片、`#E0E7FF` 边框、12px 圆角、`#4F46E5` 主色和 Inter / Noto Sans SC 字体链。正文主色为 `#334155`，标题为 `#0F172A`，弱提示为 `#94A3B8`。状态继续使用正式靛蓝、RC 青蓝、Beta 琥珀色。阴影只保留现有项目的轻量层次，不通过渐变、大面积色块或胶囊堆叠制造层级。

## 三个方向

### A．可展开树表（推荐）

保持现有表格的横向扫描效率，把软件仓库作为全宽父行，版本作为缩进子行。仓库父行显示路径、当前版本、版本数和最近发布时间；展开后版本行与原页面列完全对齐。这个方向学习 GitLab Tree 的缩进与展开符号，以及 Carbon 对「只展开一层」的约束，最接近现有交互，迁移成本最低，也便于把同一树表套入打包看板。

### B．仓库摘要卡树

每个仓库是一块轻量分组卡，卡头承载当前版本、发布数量和最近发布时间，卡内以一条纵向分支线连接版本明细。相比 A 更强调仓库是独立发布单元，适合仓库数量少但每个仓库需要展示更多状态的产品；代价是纵向空间稍大。

### C．双栏树与明细

左侧是可搜索的软件仓库—版本树，右侧是当前选中仓库或版本的明细面板。它不要求用户同时展开所有仓库，适合后续打包看板在右侧承载任务状态、构建产物和配置操作。该方案复用能力最强，但在纯「浏览全部版本」场景中不如 A 直观，因此作为工作台化备选。

## 交互规则

- 点击仓库行或展开箭头切换展开状态；搜索命中仓库名、路径、版本号或 Tag 时自动展开命中仓库。
- 默认展开最近有发布的仓库，其他仓库保持折叠；提供「全部展开／全部折叠」快速操作。
- 仓库父级显示汇总，版本子级显示发布事实，不在两个层级重复同一字段。
- 版本行点击进入发布详情；仓库名称点击时可在后续实现中进入仓库详情。
- 375px 宽度下仓库摘要换行，版本明细允许横向滚动或切换为卡片；桌面端维持中等信息密度。

## 选型建议

优先采用 A 作为统一基础组件，因为它能最小化现有页面变化，同时准确补足仓库归属。组件内部可预留 `renderRepositorySummary`、`renderVersionColumns` 和 `onSelect` 等扩展点；打包看板若需要更强的焦点式操作，可在相同数据模型上切换为 C 的双栏外壳，而不再创建第二套仓库／版本概念。
