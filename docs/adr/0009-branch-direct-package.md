# 0009 - 分支直打包（不经发布流程）

**状态:** proposed
**日期:** 2026-08-17
**决策者:** 产品/研发团队
**关联规格:** 无（需求来自按分支最新代码直接出包的使用场景）

## 背景

ADR-0002 确立的打包触发方式为「发布推 tag 成功后由 `ReleaseService` 触发」。部分场景需要
绕过发布流程，直接对仓库某条分支的最新代码打包（如验证分支联调产物、预发验证），现有流程
无法满足。打包领域约束（平台挂载约定、环境变量、产物目录、退出码语义）对分支直打包同样适用。

## 决策

1. `PackageTask.release` 改为可空（`null=True, blank=True`，迁移 `package.0020`）：分支直打包
   任务无关联发布记录；发布触发的任务行为不变。
2. 新增服务方法 `PackageService.create_task_for_branch(config, branch_name, request_user)` 与
   接口 `POST /api/packages/configs/{id}/trigger-branch/`（body 携带 `branch`）。
3. 任务命名：任务标题与自动编码（`version` / `tag_name`）均按分支名命名，便于在打包看板中识别
   来源；克隆源码使用 `git clone --branch {branch}` 拉取该分支最新代码。
4. 分支最新提交哈希（`last_commit_hash`）写入 `commit_hash` 用于可追溯；拉取失败降级为空串，不阻断打包。
5. 分支直打包无发布说明：克隆源码时跳过发布说明写入，构建环境变量 `RELEASE_DOC_PATH` 不注入，
   避免构建脚本误读不存在的文件。
6. 分支名可能包含 `/` 等路径特殊字符：发布说明文件名（`_doc_filename`）做路径安全化替换；
   SVN 推送默认模板 `{version}` 渲染后保留分支层级（如 `svn_root/feature/1.0/`），属于预期行为。
7. 任务完成/失败通知接收人：发布触发的任务通知发布人；分支直打包任务（无发布）通知触发人
   （`notify_package_result` 回退 `triggered_by`）。
8. 触发权限与「按已发布 Tag 触发」一致：项目管理员 / 开发 / 测试（`IsProjectPackager`）。
9. 分支直打包与发布流程解耦：不依赖已发布版本、不触发「发布后自动打包」（
   `trigger_auto_packages_for_release` 仅由发布流程调用）。

## 后果

- 正面：满足按分支最新代码直接出包的场景；与发布生命周期解耦；复用既有打包主流程、工作区约定、
  凭证体系与远程 Windows 执行能力。
- 反面：任务无发布记录，历史发布相关展示（如发布说明）为空；分支名直接作为版本号/目录，
  需依赖路径安全处理避免越级建目录。
- 已知限制：分支最新提交哈希依赖仓库分支数据同步，抓取失败时仅留空、不阻断打包。

## 备选方案

- 复用「按已发布 Tag」打包而不新增模式：无法打包未发布的分支最新代码，弃用。
- 前端临时伪造发布记录触发：破坏发布状态机语义、污染发布看板，弃用。
