# 0023 - 弹窗关闭后在页面内保留草稿

**Status:** accepted
**Date:** 2026-09-29
**Spec:** 无
**Deciders:** 产品/研发团队

## Context

多个表单点取消就清空。发布说明和检测 Commit 关闭时还要确认放弃修改。误关之后需要整表重填。

## Decision

1. 取消或关闭弹窗时，把当前值留在**当前组件的内存**里，按对象 key 分开存放。再次打开同一对象时恢复；打开另一个对象时，两边的草稿都还在。保存成功后只清当前对象。组件卸载后全部丢弃。
2. 凭证口令、访问令牌表单、打包节点登录相关字段同样只留在这份内存里，不写入 localStorage / sessionStorage。
3. 详情页里需要保住草稿的 tab（项目的仓库 / 成员 / 打包，仓库审批，发布说明，已发布审查）用隐藏保活，不随切 tab 卸载。隐藏时停掉该面板自己的查询，回到该 tab 再请求。
4. 发布说明编辑：没有本地改动时跟随服务端正文；有本地改动时保留到保存成功或重新生成。检测 Commit 的过滤规则仍以 ADR-0011 为准。
5. 不再为「关闭未保存」弹出确认框。

## Consequences

- 误关可以续写，换一条记录再回来也不会冲掉上一条。
- 离开页面、刷新后草稿消失。
- 隐藏 tab 不再在后台连续拉列表；切回来时按 React Query 的默认过期策略重新取数。
- 同一页面里未保存的口令留在内存中，直到该对象 `clear` 或组件卸载。

## Alternatives Considered

- 关闭即清空并确认：误关成本高，放弃。
- sessionStorage：能跨页面，也会把口令留过刷新和多标签，放弃。
- 整个详情页只保留一个草稿槽：换对象再回去会丢内容，放弃。
