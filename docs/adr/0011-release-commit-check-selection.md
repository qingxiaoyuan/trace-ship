# 0011 - 「检测 Commit」弹窗勾选加入与已填入条目过滤

**状态:** proposed
**日期:** 2026-08-18
**决策者:** 产品/研发团队
**关联规格:** 无（来自发布创建页更新内容录入的使用场景；由 code review 补录本 ADR）

## 背景

发布创建页更新内容区默认只自动填入前 10 条已解析更新，其余已解析条目和未自动解析的
Commit 需要人工处理。原有交互中「未自动解析 Commit」编辑内容后即直接加入，容易误填；
且已加入过的条目在再次打开弹窗时仍会显示，重复操作体验不佳。

## 决策

1. 「检测 Commit」弹窗按来源分两区处理，均需**勾选后才能加入**更新内容：
   - 已解析但超出自动填入上限的条目（已解析待选区）：勾选后加入；
   - 未自动解析 Commit（可编辑后加入区）：勾选后加入，支持编辑类型与内容、删除、全选/清空。
2. 已加入更新内容的条目在再次打开弹窗时自动过滤：
   - 未自动解析 Commit 区按 commit 短 hash（`source:source_ref`）过滤；
   - 已解析待选区按「类型 + 内容」（`type:content`）过滤，与创建发布页 `onAddUpdates`
     的去重语义保持一致，避免同一 commit 的多行 A/F 更新因共享 `source_ref` 被过度过滤。
3. 「检测 Commit」按钮徽标与「其余 X 条可勾选添加」提示，均实时反映**尚未加入**的可勾选条目数，
   随用户添加逐步减少，全部加入后徽标消失。
4. 弹窗关闭时若存在「已编辑但未勾选」的未解析 Commit 行，给出确认提示，避免误丢修改。

## 影响与兼容性

- 仅影响发布创建页更新内容的人工录入交互，不改动后端接口与数据模型。
- 过滤与去重均以「已存在于本地更新内容列表」为准，切换分支/发布类型后按既有逻辑重置，
  行为可预期。
- 无迁移，无接口契约变化。
