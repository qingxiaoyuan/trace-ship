# 0015 - 更新内容解析规则修订与仓库标签删除

**状态:** accepted
**日期:** 2026-08-20
**决策者:** 产品/研发团队
**关联规格:** 用户需求：修复自动扫描更新内容残留 A/F 前缀、`<feat>` 换行多条有概率扫不到；仓库详情标签支持删除、新增发布版本 Tab（由 code review 门禁补录本 ADR）

## 背景

1. 提交信息解析器（`utils/commit_parser.py::extract_update_lines`）的兜底前缀路径存在两个缺陷：
   - `feat: A 新增xxx` 这类提交，变更条目的 content 残留 `A `/`F ` 前缀，与条目类型标记重复；
   - `<feat>` / `<fix>` 前缀仅在文本首个非空行识别，标准模板中 `<feat>` 出现在「更新内容：」段落内时整块更新内容扫不到，表现为"有概率漏扫"。
2. 仓库详情页「标签」Tab 只读，历史脏 tag（格式不符、误推）无法清理；发布系统推送的 tag 只能在发布详情页通过「删除版本」连带删除，缺少独立的标签删除入口。

## 决策

### 更新内容解析规则（`extract_update_lines`）

1. 显式 `A xxx` / `F xxx` 行（含可选前导序号）扫描保持最高优先级，行为不变。
2. 前缀路径（`<feat>/<fix>/feat:/fix:`，含带 scope 的 Conventional Commit）：
   - 由「仅首个非空行」改为**逐行扫描**，标记可出现在文本任意行；
   - 支持多个前缀块混合，各块类型独立；
   - 每块收集其后内容行，遇到段落标题行（变更类型/更新内容/配置项改动/关联性改动）或下一个标记行截止；
   - 内容行统一剥离前导序号（`1. ` / `1、`）与残留的 A/F 标记，content 只保留纯内容文本，类型由系统单独标记。
3. 已知边界（接受，不处理）：
   - 前缀路径下内容行以 `A `/`F ` 开头会被当作类型标记剥离（如「A 股交易模块」），与显式路径语义一致；
   - `<feat>` 块内紧跟模板提示行 `[A为功能增加 F为BUG修复]：` 会被当作内容收集（常规模板中该行在 `<feat>` 之前，不触发）。

### 仓库标签删除

1. 新增 `POST /api/repositories/{id}/delete-tag/`，body 传 `tag_name`；仅项目管理员可操作（与「删除已发布版本」权限约定一致）。
2. 语义：调用远端 Provider 删除 tag，并同步清理本地 `RepositoryTag` 缓存行（呼应 ADR-0005 的「远端删除本地清除」口径）；远端 tag 已不存在（404）时幂等视为成功并标记 `remote_deleted=False`。
3. 前端交互：标签卡片删除按钮 → 二次确认弹窗，需输入完整 tag 名称方可执行（复用「删除已发布版本」交互）；非管理员隐藏与否暂不做，后端 403 兜底。

### 仓库详情「发布版本」Tab

复用项目详情的 `ReleaseTab` 组件，扩展 `repositoryId` 可选参数按 `repository + status=released` 过滤，不新建重复组件。

## 影响与兼容性

- 解析器：仅兜底前缀路径行为变化，显式 A/F 路径零回归；提交规范审查与发布预览共用该函数，同时受益。
- 标签删除：新增独立接口，不影响既有「删除已发布版本」链路；本地缓存清理不影响版本计算（版本计算实时读远端 + 同步重建缓存）。
- 前端：新 Tab 与删除入口均为纯增量；`ReleaseTab` 的 queryKey 由 `project-releases` 调整为 `release-tab`，无外部失效依赖。
