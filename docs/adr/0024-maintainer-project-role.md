# 0024 - 维保人员是项目成员角色

**Status:** accepted
**Date:** 2026-09-29
**Spec:** [GitHub Issue](https://github.com/qingxiaoyuan/trace-ship/issues/7)
**Deciders:** 产品/研发团队
**Extends:** ADR-0006

## Context

维保人员要在 `/dashboard` 上看所属项目里别人已经发布的版本和打包结果。PRD 初稿要求「一个用户全局只有一个角色」，并在添加成员时校验所有项目角色相同。这和 ADR-0006 冲突：角色在 `ProjectMember.role` 上按项目独立存在，同一人可以在不同项目担任不同角色。

## Decision

1. `maintainer`（维保人员）是新的项目成员角色，权限边界以 Issue #7 现行规格为准：可查看所属项目的发布与打包，可对已发布版本按已有配置触发打包、可重试失败任务；不能创建发布、审批、改打包配置、管成员。实现时补进 ADR-0006 的动作矩阵和 `get_grantable_roles`，不另做一套全局角色。
2. 不引入全局唯一角色，不在保存成员时校验「该用户在其他项目的角色必须相同」。
3. `/dashboard` 仍是唯一工作台路由，不改通用工作台布局（ADR-0022）。布局切换规则：
   - 用户全部可见项目的成员角色都是 `maintainer` 时，渲染维保工作台；
   - 没有任何可见项目，或至少一个可见项目是其他角色时，渲染通用工作台。
4. 兼任时沿用按项目授权。某个项目是维保，不收回该用户在其他项目里的开发、管理权限，也不隐藏那些项目需要的菜单。只有处于维保工作台时，才隐藏发布创建、审批和打包配置管理入口，并拦截对应直连 URL。
5. 维保工作台的数据范围仍是「我作为成员可见的项目」，统计口径是这些项目里的发布和打包，不是「我发起的」。

## Consequences

- 纯维保账号看到维保首页；开发和维保兼任的账号仍用通用工作台，维保项目从项目页进入。
- 成员管理不用为角色一致性加跨项目查询。
- 已发布版本补打、失败重试按目标项目独立授权；通用打包入口仍保持开发/测试/管理权限，避免放开分支直打或任意构建参数。

## 实现边界（2026-10-14）

Issue #23 实现按项目授予角色、项目数据只读与写入口限制。纯维保识别继续采用有效角色，负责人和超管保持原授权；兼任时每个资源仍按所属项目授权。

Issue #24 使用只读 `GET /api/releases/dashboard/context/` 统一提供布局和完整可见项目数量；首页、桌面/移动导航、快捷搜索与直连拦截共享结果。首次加载、重新进入首页及成员变更重新查询，重新激活窗口和一分钟轮询同步其他会话变化；首次加载失败提供重试，后台刷新失败保留页面与表单草稿并提示重试。纯维保首页分页展示所属项目的已发布版本，按实际发布时间倒序、缺失时间排后，项目内软件名称按组件显示。成员、打包配置及仓库设置页面的管理入口和直连路径收敛；兼任与普通工作台保持原行为。

界面采用 Penpot「溯舟 / 工作台」中的「维保 · PC 首页优化 / 发布版本」「维保 · 01–04 首页与范围筛选」与「维保 · 16 版本卡片规范」：桌面以列表展示，手机使用独立版本卡片，版本号与「发布说明」均进入现有发布详情。小字号文字在保留设计配色层次的基础上加深以保证可读性；已接入区域只展示真实接口数据，第三方问题单区域按下述边界明确标记待接入。

界面对照截图：[桌面工作台](../ui/screenshots/maintainer/desktop.jpg)、[375px 手机首页](../ui/screenshots/maintainer/mobile-375.jpg)、[手机范围选择](../ui/screenshots/maintainer/mobile-scope.jpg)。截图由真实页面连接独立测试库生成，使用虚构项目、用户与任务，供布局核对。

只读首页继续覆盖 #25 / #26 / #29 / #30 对应的组合检索、多行更新摘要、所属项目打包近况、手机范围抽屉与 KPI。`GET /api/releases/dashboard/maintainer-summary/` 返回完整范围树、近 30 天发布和终态打包统计、全时段失败任务数；总览与主列表查询条件相互独立。各版本的打包摘要按配置 ID（配置删除后回退任务快照 ID）取最近结果，避免成功任务掩盖其他配置失败。手机抽屉的临时范围仅在应用后写入 URL；关闭不提交，清空范围保留关键词与类型，恢复全部才清除全部条件。

Issue #27 在桌面已发布版本详情增加补打入口；按目标项目有效角色独立授权，只能选择同项目、同仓库的启用配置。服务端只接受发布 ID，复用固定源码身份、配置快照、仓库锁和提交后投递，手动补打不推 SVN。操作日志记录实际操作者、项目、配置、版本、新任务和投递结果；全部投递方式失败时任务进入失败状态并返回 503，页面展示错误与任务链接。手机隐藏该入口。失败重试仍由 #28 交付。第三方问题反馈单尚未接入；问题单列和「需要关注」区域保留设计位置并明确标记「待接入」，问题筛选不可用；不映射为发布整改意见，也不展示模拟问题计数。

## Alternatives Considered

- 强制全局唯一角色：实现简单，但要改 ADR-0006 的成员模型，并拒绝合法的跨项目分工，放弃。
- 兼任时用优先级决定首页：用户无法预期会看到哪一版，放弃。
