# 0024 - 维保人员是项目成员角色

**Status:** accepted
**Date:** 2026-09-29
**Spec:** [GitHub Issue](https://github.com/qingxiaoyuan/trace-ship/issues/7)
**Deciders:** 产品/研发团队
**Extends:** ADR-0006

## Context

维保人员要在 `/dashboard` 上看所属项目里别人已经发布的版本和打包结果。PRD 初稿要求「一个用户全局只有一个角色」，并在添加成员时校验所有项目角色相同。这和 ADR-0006 冲突：角色在 `ProjectMember.role` 上按项目独立存在，同一人可以在不同项目担任不同角色。

## Decision

1. `maintainer`（维保人员）是项目成员角色，权限边界以 Issue #7 现行规格为准：仅查看所属项目的信息，包含发布、说明、打包任务、在线日志和产物元信息；不下载文件、导出说明、补打、重试、收藏打包配置或执行项目业务写入。不另做一套全局角色。2026-10-20 的只读收权见 Issue #44，详见下文。
2. 不引入全局唯一角色，不在保存成员时校验「该用户在其他项目的角色必须相同」。
3. `/dashboard` 仍是唯一工作台路由，不改通用工作台布局（ADR-0022）。布局切换规则：
   - 用户全部可见项目的成员角色都是 `maintainer` 时，渲染维保工作台；
   - 没有任何可见项目，或至少一个可见项目是其他角色时，渲染通用工作台。
4. 兼任时沿用按目标项目的有效角色授权。某个项目是维保，不收回该用户在其他项目里的开发、管理权限，也不隐藏那些项目需要的菜单；负责人、软件管理员和超管继续按既有规则授权。无论使用哪个工作台，目标项目为维保时都须隐藏该项目的操作入口并拒绝直接请求；纯维保工作台另收敛发布创建、审批和配置管理等全局导航及直连 URL。
5. 维保工作台的数据范围仍是「我作为成员可见的项目」，统计口径是这些项目里的发布和打包，不是「我发起的」。
6. 信息查看包含检索、筛选、分页、范围切换和日志重新加载；产物只展示名称、大小等元信息。在线日志读取与日志文件下载分别授权，不以 GET 方法或只隐藏按钮代替服务端权限判断。个人消息、账号等既有个人操作不属于项目业务收权范围。

## Consequences

- 纯维保账号看到维保首页；开发和维保兼任的账号仍用通用工作台，维保项目从项目页进入。
- 成员管理不用为角色一致性加跨项目查询。
- 维保项目不再授予下载、导出、补打、重试或配置收藏能力；通用下载、导出和打包功能对其他角色的既有授权继续保留。

## 实现边界（2026-10-14）

Issue #23 实现按项目授予角色、项目数据只读与写入口限制。纯维保识别继续采用有效角色，负责人和超管保持原授权；兼任时每个资源仍按所属项目授权。

Issue #24 使用只读 `GET /api/releases/dashboard/context/` 统一提供布局和完整可见项目数量；首页、桌面/移动导航、快捷搜索与直连拦截共享结果。首次加载、重新进入首页及成员变更重新查询，重新激活窗口和一分钟轮询同步其他会话变化；首次加载失败提供重试，后台刷新失败保留页面与表单草稿并提示重试。纯维保首页分页展示所属项目的已发布版本，按实际发布时间倒序、缺失时间排后，项目内软件名称按组件显示。成员、打包配置及仓库设置页面的管理入口和直连路径收敛；兼任与普通工作台保持原行为。

界面采用 Penpot「溯舟 / 工作台」中的「维保 · PC 首页优化 / 发布版本」「维保 · 01–04 首页与范围筛选」与「维保 · 16 版本卡片规范」：桌面以列表展示，手机使用独立版本卡片，版本号与「发布说明」均进入现有发布详情。小字号文字在保留设计配色层次的基础上加深以保证可读性；已接入区域只展示真实接口数据，第三方问题单区域按下述边界明确标记待接入。

界面对照截图：[桌面工作台](../ui/screenshots/maintainer/desktop.jpg)、[375px 窄屏首页](../ui/screenshots/maintainer/mobile-375.jpg)、[窄屏范围选择](../ui/screenshots/maintainer/mobile-scope.jpg)。截图由真实页面连接独立测试库生成，使用虚构项目、用户与任务，供布局核对；浏览器窄屏模拟不代表手机真机或系统软键盘验收。

只读首页继续覆盖 #25 / #26 / #29 / #30 对应的组合检索、多行更新摘要、所属项目打包近况、手机范围抽屉与 KPI。`GET /api/releases/dashboard/maintainer-summary/` 返回完整范围树、近 30 天发布和终态打包统计、全时段失败任务数；总览与主列表查询条件相互独立。各版本的打包摘要按配置 ID（配置删除后回退任务快照 ID）取最近结果，避免成功任务掩盖其他配置失败。手机抽屉的临时范围仅在应用后写入 URL；关闭不提交，清空范围保留关键词与类型，恢复全部才清除全部条件。

历史交付中，Issue #26 补齐日志、产物下载与异常反馈；Issue #27 在桌面已发布版本详情增加按已有配置补打，包含固定源码身份、配置快照、仓库锁、提交后投递、实际操作者审计以及投递失败反馈，手机隐藏补打入口。这些记录说明当时的交付范围，不再作为维保具有下载或补打权限的依据。

## 只读收权（2026-10-20）

用户明确维保只需要查看信息，下载、导出、重新打包等操作均不需要。Issue #7 的现行规格以及本 ADR 的 Decision / Consequences 已据此修订；该需求取代此前维保下载、补打与失败重试的例外授权。

Issue #44 撤回维保下载、导出、补打和打包配置收藏的前端入口及服务端授权，同时保留在线发布说明、在线日志、任务与产物元信息的读取；桌面和手机遵循同一角色边界。日志接口使用 `tail` / `offset` 参数返回在线 JSON，省略两者的完整日志文件请求则对维保返回 403。配置收藏和补打还在服务层按锁定后的当前配置所属项目重新验权，不仅依赖页面或视图最初的角色判断。

Issue #29 继续完善手机只读浏览：检索、筛选、分页与项目范围切换保持可用，版本卡片进入完整发布说明，返回后恢复范围、页码和浏览位置。宽表仅在正文表格内横向滚动，长名称和搜索输入适配 375px 视口。验收须分别记录说明内容、DOM 语义与布局；浏览器模拟视口和输入焦点检查不能代替手机真机及系统软键盘验证。

Issue #28 已按不再计划关闭，维保失败重试不再列入待办。历史 Issue #26 / #27、操作审计和交付证据保留；它们建立的通用下载、打包、固定源码校验、投递保护、回归测试与 CI 资产不整体回退，继续用于其他获授权角色。兼任账号按目标项目校验，不能借另一项目的开发角色或共享仓库绕过维保项目限制。

第三方问题反馈单尚未接入；问题单列和「需要关注」区域保留设计位置并明确标记「待接入」，问题筛选不可用；不映射为发布整改意见，也不展示模拟问题计数。

## Alternatives Considered

- 强制全局唯一角色：实现简单，但要改 ADR-0006 的成员模型，并拒绝合法的跨项目分工，放弃。
- 兼任时用优先级决定首页：用户无法预期会看到哪一版，放弃。
