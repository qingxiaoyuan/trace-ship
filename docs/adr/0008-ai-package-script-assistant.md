# 0008 - AI 打包脚本助手（Beta）

**状态:** proposed
**日期:** 2026-08-14
**决策者:** 产品/研发团队
**关联规格:** 无（需求来自打包脚本调试学习成本高的痛点）

## 背景

打包脚本调试难、学习成本高。希望借助 AI 生成打包脚本初稿并逐行解释，
降低使用门槛。打包脚本领域约束明确（平台挂载约定、环境变量、产物目录、
退出码语义），属于适合 LLM 的窄任务。

## 决策

1. AI 调用放在后端：兼容 OpenAI / Anthropic 协议，服务参数（endpoint / key /
   model / protocol）存 `sys_config`，Key 不暴露给前端；调用留操作日志。
2. 生成上下文由四部分注入：
   - 平台执行约定 + 打包配置（执行方式、镜像、构建/产物目录、环境变量）；
   - 仓库清单（GitLab API 文件树 + 关键清单文件，失败降级不阻断）；
   - 本地 Docker 镜像 / 远程 Windows 节点只读工具探测（失败仅警告）；
   - 系统级「打包知识库」与历史成功任务脚本参考（同项目优先、跨项目兜底，
     开关默认开启，可关闭）。
3. 结果只作为草稿：前端弹窗展示脚本与逐行解释，用户确认后才写回配置，
   不自动保存、不自动执行。
4. 历史脚本注入前做明文凭据脱敏；仓库凭证、敏感环境变量值永不进入 prompt。
5. 知识库为系统级通用，通过 `/api/packages/knowledge/` 维护，写操作需
   `system.config` 权限。
6. 生成采用 SSE 流式接口（`/api/packages/configs/ai-generate-script-stream/`）：
   后端以线程 + 队列转发 OpenAI/Anthropic 的流式片段，前端实时展示进度与
   输出；网关不支持流式时自动回退非流式调用。
7. 上下文体积上限可配置（`sys_config` 的 `ai_manifest_chars` /
   `ai_tree_chars` / `ai_knowledge_chars` / `ai_exemplar_chars`，默认
   32768 / 15000 / 12000 / 12000），操作日志记录 `prompt_chars` 与
   `prompt_tokens_est` 用于观测；解析失败重试仅对 ≤40000 字符的短 prompt
   生效；AI 超时 300 秒、`max_tokens` 4096。
8. 保留远程 Windows 节点 SSH 只读工具探测（超时 30 秒，失败降级仅警告），
   输出上限约 8KB；本地 Docker 镜像探测保留。

## 后果

- 正面：脚本上手成本降低；上下文透明（引用来源可见）；失败降级不阻塞主流程。
- 反面：脚本正确性依赖上下文质量与模型能力，仍是 Beta；外部 AI 调用有成本，
  已加 15 秒/用户+项目频控与上下文体积上限。
- 已知限制：SSE 客户端断开后无法中断已发出的 AI 请求（后台线程继续跑完），
  会产生无效消耗，后续可加取消机制。

## 备选方案

- 前端直连 AI：实现简单但 Key 暴露、无法后端扫仓库，弃用。
- 生成时后端临时克隆仓库：可拿全量上下文但重且依赖 git 环境，弃用。
- 纯人工编写脚本：学习成本高，与目标相悖。
