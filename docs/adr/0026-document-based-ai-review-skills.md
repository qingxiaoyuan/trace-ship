# 0026 - 审查技能作为文档资源，由平台提供只读执行能力

状态：accepted，2026-10-28。用户已确认[规格 #58](https://github.com/qingxiaoyuan/trace-ship/issues/58)为完整开发与验收基线，包含默认技能、可选审查上下文和八项验收边界；本决策不表示功能已经实现。

发布审批需要支持内置与管理员上传的审查技能，同时使用系统配置的模型执行审查。第一期将技能限定为审查指引与参考文档：接受单个 `SKILL.md` 或包含它与参考文档的 ZIP，由平台提供只读代码读取、搜索、差异获取及并行审查能力，不执行上传包中的脚本或安装命令。

这一选择保留了按技能步骤组织审查和扩充审查规则的能力，也避免将上传权限等同于服务端代码执行权限。代码与规范读取、差异分析及并行审查由平台提供；代价是不承诺任意 Agent Skill 包都能原样执行，依赖脚本或外部命令的技能需要适配至平台支持的能力。通用 Agent 运行环境不属于本次已确认范围。

模型连接统一复用打包脚本生成的 AI 服务设置（地址、密钥、模型名称、协议），默认审查技能单独选择。节点只表达“执行 AI 代码审查”，不承担技能上传管理。每轮提审固定技能版本、模型配置与代码范围，普通失败重试沿用该轮配置；设置更新影响后续新提交的审批，退回修改后重新提审采用届时的设置，历史报告与旧技能版本保持可追溯。

所选技能决定审查重点，平台统一保证报告结构、代码范围、行号校验、权限和人工审批规则。技能可以聚焦安全、性能等领域，报告必须明确实际覆盖的维度，不承诺每个自定义技能都执行相同三轴。

默认内置选用用户已确认的 [sanyuan0704/sanyuan-skills 的 code-review-expert](https://github.com/sanyuan0704/sanyuan-skills/tree/08b6572ef108f22d4e8a3ecf9182a4bbef097744/skills/code-review-expert)，来源快照为 `08b6572ef108f22d4e8a3ecf9182a4bbef097744`。该技能由主文档和四份 Markdown 检查清单组成，已有严重度与文件行号意见格式，不依赖 Matt 事项工作流；平台不内置 Matt code-review。

接入时需把工作区差异改为本轮固定版本差异，将交互式询问修复步骤交给平台已确定的整改闭环，并将严重度作为人工判断信息，不直接执行原文中的自动阻断建议。平台仍须校验结构化结果和行坐标，保留上游来源、MIT 许可及适配版本。此处记录已确认的选型与适配边界；选型时未安装或复制远端技能，后续实现以固定来源版本纳入主文档和参考文件。

## 2026-10-29 配置复用调整

按用户在 #75 的明确要求，将原独立审查模型改为复用脚本 AI 的 `ai_*` 模型连接配置。新提审读取当时的共享参数并与审查技能形成不可变、密钥加密的版本；旧版本保留，已提审及重试不切换模型。共享模型未配置时拒绝新提审，不回退旧独立模型；只有脚本模型已配置的存量环境可直接采用内置审查技能。审查技能保存入口不再接受模型及密钥字段，脚本上下文与输出额度仍只用于脚本生成。

共享模型页面通过一次请求、一个事务保存整组参数；模型保存、技能保存与提审快照共用配置锁，提审只捕获保存前或保存后的完整模型。保存失败全部回滚，不固定地址和密钥来自不同保存阶段的组合。密钥未编辑时省略并保留，显式空值表示清除。通用配置表仅展示并链接模型设置，通用写接口拒绝四个模型键的新增、修改、改名和删除，防止旧入口重新产生半份配置。
