# 0020 - 产品通过所有者成员关系组合可复用仓库，发布保持仓库级

**Status:** accepted
**Date:** 2026-09-11
**Spec:** `docs/requirements/PRD-产品仓库组合与版本管理.md`（凭证授权已按本 ADR 修订）
**Deciders:** 产品/研发团队

## Context

同一物理仓库会被多个产品使用。原先仓库直接归属项目，导致重复登记、凭证和版本互相覆盖。发布目标应是仓库而不是产品组合；产品只负责关联、权限和产品内配置。

凭证不能改成共享服务账号。授权方式选择「仓库所有者必须是产品成员」，而不是每次发布再选一条借用记录。

## Decision

1. 现有 `Project` 即产品，不新增平行 Product 模型。
2. 物理仓库按 `vendor + url + external_identity` 全局唯一；`Repository.project` 仅作兼容字段。
3. 产品通过 `ProductComponent` 关联仓库。关联前仓库所有者（`created_by`，无则回退绑定凭证归属人）必须已是该产品成员。
4. 仓库绑定的个人凭证必须属于仓库所有者。产品关联成功后，该产品发布、同步、打包使用这份凭证。
5. 版本和 Tag 属于仓库。A、B 产品都可以对同一仓库发版本，共享同一套序列。不做产品组合发布，也不做产品级版本隔离。
6. 创建发布必须存在当前产品下启用中的关联；停用关联后不能再发。打包配置不能自动补建关联。
7. `RepositoryCredentialLoan` / `CredentialUsageLog` 保留为补充审计，不是关联产品或使用凭证的主路径。

## Consequences

- 要把仓库给新产品用：先把仓库所有者拉进该产品成员，再关联仓库。
- 所有者被移出产品前，须先停用或移除其作为所有者的仓库关联。
- 自动打包仍按本次发布的 `project + repository` 隔离，不会打到另一个产品。
- 存量借用表不删除，以免破坏已执行的迁移；界面不再把它当作授权入口。

## Alternatives Considered

- 显式 `RepositoryCredentialLoan` 作为主授权：范围更细，但发布主路径容易绕过，操作成本高。
- 产品级版本 / Tag 命名空间：与「版本属于仓库」冲突，已放弃。
