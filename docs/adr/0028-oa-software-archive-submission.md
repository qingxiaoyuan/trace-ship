# 0028 - OA 软件归档保留独立申请与产物依据

**状态：** 已接受；#104—#108 已提供配置、首次与再次申请、人工核对重试、结果历史、来源保护及历史 SVN 当前文件与补录。整体验证与交付进度见 #103 及集成 PR。
**日期：** 2026-11-12
**规格：** [#103 正式版本打包后填写资料并发起 OA 软件归档](https://github.com/qingxiaoyuan/trace-ship/issues/103)

正式版本发布并完成打包后，用户选择一个产物，核对可编辑的资料，再向 OA 发起一份软件归档申请。OA 接口接收产物 SVN 地址，不接收文件本体；创建流程成功只表示“已发起归档”，不表示 OA 审批通过或归档完成。

每次申请保留独立的提交资料、实际操作者、来源发布与产物依据，以及 OA 返回结果。弹窗修改不反向改写发布或项目资料；同一产物已成功申请后仍允许显式再次办理，提交前提醒已有记录，新申请不覆盖旧申请。因此防抖约束的是同一次提交及并发中的重复请求，不是“一产物终身只准归档一次”。

本地产物保留期与归档办理资格分开：只要对应 SVN 文件仍存在，本地文件清理后仍可发起申请。产物关联信息的保留不能继续绑定本地大文件清理周期；历史已丢失的元数据不能伪造，SVN 查询也必须区分文件缺失与网络、凭证导致的无法核验。

历史归档按 SVN 当前存在的文件办理。有原上传清单时恢复候选并实时核验；没有清单时，允许在该任务保存的 SVN 目录内手选，并标明“从 SVN 补录”。SVN 目录可能被覆盖，因此当前位置有文件不等于仍是当年的构建内容；本期不要求恢复或证明原构建文件身份，不把当前文件元数据伪装成原始构建证据。

已经发起 OA 归档的发布和打包任务增加删除保护，保留详情与申请历史；本地文件仍按原保留期清理。该决定有意收紧已有删除入口，避免发布删除连带清掉打包记录后，OA 中的单据失去可查询的来源。明确失败且确认未建单的申请不触发此保护。

OA 未提供防重复或查单接口。请求超时后保留“结果未确认”和本次资料，不自动重发，由用户核对 OA 后主动重试。此处选择保留不确定结果而非自动重试，是因为本系统防抖只能防止自身重复派发，无法证明超时请求没有在 OA 创建单据。
