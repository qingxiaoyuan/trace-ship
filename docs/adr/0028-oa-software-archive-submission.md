# 0028 - OA 软件归档保留独立申请与产物依据

**状态：** 已接受；#104—#108 已提供配置、首次与再次申请、人工核对重试、结果历史、来源保护及历史 SVN 当前目录与补录。整体验证与交付进度见 #103 及集成 PR。
**日期：** 2026-11-12；2026-11-13 按用户确认改为完整产物目录
**规格：** [#103 正式版本打包后填写资料并发起 OA 软件归档](https://github.com/qingxiaoyuan/trace-ship/issues/103)

正式版本发布并完成打包后，用户从发布详情顶部选择某次成功打包的整个产物根目录，核对可编辑的资料，再向 OA 发起一份软件归档申请。OA 接口的 `git_svn` 接收代码 Git 分支名，按发布记录预填且允许修改，缺失时留空可补填；产物目录按保存依据独立核验，不接收文件本体；创建流程成功只表示“已发起归档”，不表示 OA 审批通过或归档完成。

每次申请保留独立的提交资料、实际操作者、来源发布与产物依据，以及 OA 返回结果。弹窗修改不反向改写发布或项目资料；同一产物已成功申请后仍允许显式再次办理，提交前提醒已有记录，新申请不覆盖旧申请。因此防抖约束的是同一次提交及并发中的重复请求，不是“一产物终身只准归档一次”。

本地产物保留期与归档办理资格分开：只要保存的 SVN 目录仍含可用交付文件，本地文件清理后仍可发起申请。产物关联信息的保留不能继续绑定本地大文件清理周期；历史已丢失的元数据不能伪造，SVN 查询也必须区分文件缺失与网络、凭证导致的无法核验。

历史归档按任务保存的 SVN 当前根目录办理，不选择目录内部的单文件或任意子目录。选择与发送均实时核验路径确为目录且含有效交付文件，只有系统生成发布说明不算交付物。原清单缺失时按整个目录补录并标明“从 SVN 补录”。SVN 目录可能被覆盖，因此当前内容不等于当年的构建内容；原文件清单及已知元数据与当前目录 revision、文件清单分别保存。无 SVN 时要求实际本地产物仍存在。

目录身份使用任务与根路径 `.`，不同任务仍独立。旧单文件请求保持兼容，旧申请继续使用原文件相对路径，不迁移、不冒充目录申请。新界面只提供整个目录选择；顶部入口不依赖当前打开哪个详情标签，历史仍位于打包任务区域。此决定取代早期单文件选择，不涉及文件上传、打 ZIP 或冻结 SVN 内容。

已经发起 OA 归档的发布和打包任务增加删除保护，保留详情与申请历史；本地文件仍按原保留期清理。该决定有意收紧已有删除入口，避免发布删除连带清掉打包记录后，OA 中的单据失去可查询的来源。明确失败仍保留保护；当前有归档权限的操作者可独立核对并确认未建单，保存确认人、时间与依据，原子且幂等解除本条失败申请的保护。无需重试即可确认，其他历史申请的保护不受影响；原资料、失败响应与结果保持不变。

OA 未提供防重复或查单接口。请求超时后保留“结果未确认”和本次资料，不自动重发，由用户核对 OA 后主动重试。此处选择保留不确定结果而非自动重试，是因为本系统防抖只能防止自身重复派发，无法证明超时请求没有在 OA 创建单据。
