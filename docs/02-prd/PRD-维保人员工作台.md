# 维保人员定制化首页工作台需求

## 1. 文档信息

- 状态：已确认，待实施
- 核心结论：新增项目成员角色「维保人员」（ADR-0024，沿用 ADR-0006 的按项目授权）。工作台仍是 `/dashboard`。用户全部可见项目的成员角色都是维保时，自动切换到以「已发布版本 + 打包情况」为核心的布局；只要有一个项目是其他角色，就用通用工作台。数据范围仍限定为其所属项目。
- 明确排除：不改变现有通用工作台的内容与布局；不为维保人员开放发布创建、审批、打包配置管理等能力；不新建独立的维保工作台路由。

## 2. 背景与问题

现有工作台（Dashboard）面向「发布/打包参与者」设计：

- KPI 与打包数据的口径是「我发起的」任务；
- 待办面板面向审批人（待我审批）；
- 发布流水线面向创建发布的研发角色。

维保人员的实际工作视角相反：他们不发起发布、不参与审批，核心诉求是**看别人做的发布结果**——软件发布了哪些版本、每个版本变了什么，打包交付物的情况作为辅助关注。继续使用通用工作台会出现大面积与己无关的区域（待我审批恒为空、流水线恒为空、KPI 口径错误），关键信息反而需要跳转多个页面才能看到，也缺少按项目/产品过滤和关键词检索发布信息的入口。

## 3. 目标与非目标

### 3.1 目标

1. 维保人员登录后，首页以「版本发布信息」为第一优先级呈现最近发布的版本，打包情况作为辅助信息。
2. 首页支持对发布信息的关键词搜索（版本号、软件名、发布说明内容）与按项目/产品 → 软件（仓库）两级、发布类型的过滤；发布信息需呈现「项目/产品 → 软件 → 版本」的层级归属。
3. 从首页可一键进入发布详情和发布变更文档（发布说明），并支持导出。
4. 打包情况可观察、可操作：查看任务状态与日志入口，失败任务可重试，已发布版本可手动触发打包。
5. 同一个 `/dashboard` 路由按 ADR-0024 自动切换布局：全部可见项目都是维保时用维保版，否则用通用版。
6. PC 端完整呈现发布与打包信息；移动端（按 ADR-0014 约定）聚焦发布信息：搜索、树形筛选、发布说明查看与导出，不承载打包面板与打包操作。
7. 数据范围遵守现有规则：维保人员只能看到其所属项目的发布与打包数据。

### 3.2 非目标

以下能力不属于本需求，界面、接口中均不应出现：

- 维保人员创建发布、提交审批、执行审批。
- 维保人员新建/修改/删除打包配置。
- 跨项目的数据聚合视图（如全公司发布总览）。
- 独立的维保工作台路由或导航入口。
- 对现有通用工作台布局的改版。

## 4. 角色定义与权限边界

### 4.1 维保人员（maintainer）

维保人员是面向软件交付后环节的查看与运维角色，典型工作是：确认版本已发布、向客户/现场提供发布变更说明、确认打包产物已产出、在产物缺失或打包失败时发起补打。

角色身份规则（ADR-0006、ADR-0024）：

- 维保是 `ProjectMember.role` 的一个取值，按项目授予。同一用户可以在 A 项目是维保、在 B 项目是开发。
- 添加或修改成员时不做跨项目角色一致性校验。
- 可见项目 = 其作为成员加入的项目，与现有数据可见性规则一致。
- 工作台布局不按「全局唯一角色」切换，规则见 6.1。

### 4.2 权限边界

| 能力域 | 允许 | 禁止 |
| --- | --- | --- |
| 发布 | 查看所属项目的发布列表、发布详情、发布说明、发布关联提交/MR；导出发布说明（PDF/Word/Markdown） | 创建发布、编辑发布说明、提交审批、审批操作、撤销/回退流程 |
| 打包 | 查看所属项目的打包任务列表、任务详情、日志、产物下载；对已发布版本手动触发打包（选择已有打包配置）；重试失败任务 | 新建/修改/删除打包配置、管理打包镜像与节点、取消他人任务 |
| 项目 | 查看所属项目及其仓库、组件信息 | 成员管理、项目配置、仓库登记/关联 |

权限实现上，维保角色需要在打包触发与重试接口上放行（现有权限校验面向开发/管理角色），其余能力复用现有只读权限即可。

## 5. 用户流程

### 5.1 查看最新发布

1. 维保人员登录，进入 `/dashboard`，系统识别其角色为维保，渲染维保版工作台。
2. 首屏以「版本发布信息」为主体：所属项目范围内、状态为已发布的发布记录，按发布时间倒序，每条附带该版本的打包状态摘要。
3. 列表上方提供关键词搜索（匹配版本号、软件名、发布说明内容）与「项目/产品 → 软件（仓库）」两级联动过滤器、发布类型过滤器；搜索与过滤仅在所属项目数据范围内生效。
4. 输入关键词或选择过滤器后列表实时收窄，并显示匹配数量；无匹配时给出空态提示。
5. 点击某条进入发布详情页（`/releases/:id`）。

### 5.2 查看与获取发布变更文档

1. 在最近发布列表或发布详情中打开发布说明（Markdown 渲染）。
2. 需要对外提供时，使用详情页现有导出能力导出 PDF / Word / Markdown。

### 5.3 关注与处理打包

1. 首页「打包情况」面板展示所属项目的最近打包任务：关联版本、状态、触发方式、耗时、产物入口。
2. 失败任务在面板中突出显示，维保人员可查看日志定位原因。
3. 确认为环境或临时问题后，对失败任务执行重试。
4. 某已发布版本缺少产物时，从该版本的发布详情或打包面板发起手动打包，选择项目内已有打包配置执行。

## 6. 规则

### 6.1 首页切换规则

- `/dashboard` 为唯一工作台路由。
- 用户每个可见项目的成员角色都是维保时，渲染维保版。没有可见项目，或至少一个可见项目是其他角色时，渲染现有通用版。
- 角色以后端的项目成员记录为准，不在前端猜一套全局角色，也不提供手动切换布局。
- 兼任其他角色时，菜单和直连 URL 沿用按项目授权。只有处于维保版工作台时，才隐藏发布创建、审批和打包配置管理入口。

### 6.2 数据口径规则

- 维保版工作台的所有统计与列表口径为「我所属项目的」，区别于通用版的「我发起的」。
- 最近发布列表：所属项目 + `released` 状态，按发布时间倒序。
- 打包任务列表：所属项目的全部任务（含他人触发），不限于本人发起。
- KPI 口径（详见 7.1）：近 30 天所属项目发布版本数、所属项目打包成功率、当前失败任务数。
- 关键词搜索与过滤器只收窄发布信息的展示范围，不扩大数据可见边界：任何搜索/过滤条件下，结果集都不超出「所属项目」。
- 本文「软件」指项目内通过 `ProjectComponent` 关联的软件仓库（项目内展示名）；发布版本归属于软件，展示与检索均需体现「项目/产品 → 软件 → 版本」三级层级。
- 过滤控件以「项目 → 软件」树形结构呈现（软件从属于项目，不使用平行的项目/软件双 Tab）；PC 端为树形导航或树形下拉，移动端树形面板以底部抽屉展开。

### 6.3 操作约束

- 手动触发打包仅允许基于**已发布版本**和**项目内已有打包配置**，维保人员不能临时填写构建参数。
- 重试仅针对终态为失败的任务，且沿用该任务原配置。
- 维保人员的触发与重试操作计入操作日志，任务记录中保留实际操作人。

### 7.2 验收场景

#### 场景一：登录进入维保版工作台

1. 维保账号登录后进入 `/dashboard`。
2. 页面渲染维保版布局：KPI（维保口径）、最近发布列表、打包情况面板。
3. 不出现「待我审批」「发布流水线」「新建发布」「导出周报」等研发向区域。
4. 开发/经理账号登录同一路由，仍看到现有通用版，行为不变。

#### 场景二：检索发布与查看变更文档

1. 最近发布列表仅包含该维保人员所属项目的已发布记录。
2. 列表中每条发布可清晰识别其「项目/产品 → 软件 → 版本」层级归属。
3. 输入关键词（如版本号片段、软件名），列表实时过滤并显示匹配数量。
4. 选择某一项目/产品后，软件过滤器联动为该项目的软件列表；再选某一软件，仅显示该软件的发布；与关键词、类型过滤可叠加。
5. 搜索一个不存在的版本号时显示空态提示，不出现任何所属项目之外的数据。
6. 点击某版本进入 `/releases/:id`，发布说明正常渲染。
7. 导出 PDF/Word/Markdown 均可下载且内容完整。

#### 场景三：打包观察与处理

1. 打包面板展示所属项目全部最近任务（含他人触发）。
2. 失败任务有醒目标识，可进入任务详情查看日志。
3. 对失败任务执行重试，生成新任务并沿用原配置；任务记录操作人为该维保账号。
4. 在已发布版本的详情页发起手动打包，只能从该项目已有打包配置中选择。

#### 场景四：权限负向验证

1. 维保账号直接访问 `/releases/create`、工作流审批、打包配置管理页面，被拦截或重定向。
2. 调用发布创建、审批、打包配置写接口，返回无权限。
3. 请求非所属项目的发布/打包数据，返回为空或无权。

#### 场景五：按项目授予

1. 将已是 A 项目维保的用户以开发角色加入 B 项目，保存成功。
2. 该用户进入 `/dashboard` 看到通用工作台，仍可在 B 项目创建发布。
3. 移除 B 项目成员关系、只保留维保项目后，下一次进入 `/dashboard` 渲染维保版。

#### 场景六：移动端

1. 移动端只呈现发布信息：搜索、树形筛选、版本列表/时间线、发布说明查看与导出；不展示打包面板、打包状态徽标与打包操作（重试/手动打包仅 PC 端）。
2. 375px 宽度下版本卡片化（版本号 + 类型徽标 + 「项目 / 软件 · 时间」meta + 主操作），不出现横向溢出。
3. 可点按钮触控目标不小于 36px；弹窗/抽屉 ≤768px 自动贴底。
4. 页面底部为 `MobileTabBar` 留出空间，不被遮挡。

## 8. 复用与改动点

### 8.1 可直接复用

- 发布列表/详情/发布说明/导出：`frontend/src/api/release.ts` 与 `frontend/src/pages/Release/` 现有能力，无需新接口。
- 打包任务列表/详情/日志/产物下载：`frontend/src/api/package.ts` 与 `frontend/src/pages/Package/` 现有能力。
- 列表卡片化、面板组件模式：参照现有 Dashboard 的 `RecentReleasesPanel` 及其移动端行渲染。

### 8.2 需要新增/调整

- 角色体系：新增项目成员角色 `maintainer`（ADR-0024）。不落地全局唯一角色。
- 前端：`/dashboard` 增加按角色选择布局的分支，新增维保版布局组件（KPI、最近发布、打包情况三块），按 ADR-0014 做移动端增量适配。
- 后端：打包触发与重试接口对维保角色放行；维保 KPI 若现有统计接口（按「我发起的」口径）不满足，需新增「我所属项目的」口径统计接口或参数。
- 菜单与路由守卫：维保角色隐藏新建发布、审批、配置管理类入口，并对直连 URL 做拦截。

### 8.3 移动端适配要求

- 只做增量适配：沿用 Tailwind 断点，追加 `max-md:`/`sm:`/`md:` 前缀类，不改动桌面样式。
- `<lg` 时操作集中于底部 `MobileTabBar`，不为维保版新建菜单源。
- Modal/Drawer 不写定位覆盖，由全局媒体查询贴底。
- 新面板自检：375px 搜索区不溢出、列表卡片化、触控目标 ≥36px、内容区底部留出操作栏空间。
- 移动端范围收敛：仅呈现发布信息（搜索 / 树形筛选 / 版本列表 / 发布说明 / 导出），打包面板、打包状态徽标与打包操作（重试、手动打包）一律不在移动端展示。
